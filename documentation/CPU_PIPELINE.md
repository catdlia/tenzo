# ⚙️ Модуль: CPU Optimization Pipeline (x86 AVX2)

Це серце компілятора, де високорівневі тензорні операції перетворюються на максимально швидкий машинний код, з фокусом на LLM інференс (BitNet 1.58B).

## 📂 Структура файлів
*   **`LinalgLowering.cpp`**: Оптимізація графа на рівні MLIR, опускання до векторних мікро-ядер (BitLinear, RoPE, RMSNorm).
*   **`BitLinearTL1PackLoweringToLinalg`**: Спеціалізоване AVX2 мікро-ядро для `tenzo.bitlinear_tl1`.
*   **`PackingPass.cpp`**: Переупорядкування матриць у пам'яті (BLIS-style).
*   **`ExplicitMicroKernel.cpp`**: Старе FMA мікро-ядро для MatMul.

## 🛠 Ключові етапи обробки (BitNet LLM)

### 1. Бітове пакування `tl1_pack`
**Принцип роботи:** Тернарні ваги $w \in \{-1, 0, 1\}$ BitNet 1.58B пакуються в 4 біти для різкого зменшення споживання пам'яті (851 MB для 2B моделі).
*   **Формула пакування:** `(w_even+1) | ((w_odd+1)<<2)`
*   Оскільки ваги зміщуються у $\{0, 1, 2\}$, після бітового злиття індекси виходять `0, 1, 2, 4, 5, 6, 8, 9, 10`.
*   Ці індекси ідеально поміщаються у 4-бітний нібл (від 0 до 15), що дозволяє використовувати апаратну інструкцію `pshufb` як LUT (Look-Up Table) для деквантизації та множення.

### 2. AVX2 256-bit Micro-Kernel (BitLinear)
**Принцип роботи:** Створює найбільш оптимізований цикл, який виконується повністю в регістрах AVX2 (YMM0-YMM15) без spilling-у у стек.
*   **Unroll x2 & Zero Register Spilling:** Цикл розгорнуто в 2 рази для обробки 32 байтів за такт, що ідеально вписується у 16 доступних YMM регістрів (ваги, LUT, акумулятори, маски). Розгортання x4 призводить до register spilling-у і деградації продуктивності.
*   **Дублювання LUT:** Оскільки інструкція `vpshufb` (AVX2) працює незалежно у двох 128-бітних лейнах, ми дублюємо 16-байтну таблицю LUT (побудовану з активного токена) за допомогою `vinserti128`, що дозволяє обробляти 64 вихідних канали за одну інструкцію.
*   **Prefetch:** Явний `memref.prefetch` для ваг запобігає затримкам кешу.

### 3. Zero-Allocation Bufferization
**Принцип роботи:** Уникання будь-яких динамічних алокацій (`malloc`/`free`) на гарячому шляху.
*   **Метод:** Замість `memref.alloc` у циклах використовуються `tensor.empty` та `linalg.generic`.
*   Пас `OneShotBufferize` у MLIR аналізує ці тензорні операції і статично виділяє пам'ять (або перевикористовує існуючі буфери), що зберігає накладні витрати пам'яті на нульовому рівні під час інференсу (деградація TTFT/Decode швидкості усувається).

### 4. Явна векторизація RoPE
**Принцип роботи:** Rotary Positional Embeddings (RoPE) потребують тригонометричних операцій.
*   Стандартний `linalg.generic` може розпастися до скалярних викликів `libm` (`sin`/`cos`), що повільно.
*   Впроваджено явну обробку комплексних чисел (або оптимізовані цикли) та `tensor.empty`, що запобігає алокаціям і звалюванню у скалярний код.

## 🔄 Пайплайн компіляції (LLM)
1.  **BitNet Exporter (Python)** -> `model.mlir` з `tenzo.bitlinear_tl1`.
2.  **Linalg Lowering** -> Векторизація до AVX2 `vpshufb` (unroll x2).
3.  **Bufferization** -> Перехід від тензорів до пам'яті (zero-allocation).
4.  **LLVM JIT** -> Фінальна компіляція в машинний код.

## 💡 Використання
Запускається автоматично при виклику `tenzo-cli generate`.
Для FMA-матриць використовується F32 мікро-ядро (`make cpu`).
