# 💻 Модуль: Hardware Abstraction Layer (HAL)

Цей модуль дозволяє компілятору Tenzo адаптуватися під конкретне залізо (CPU/GPU) під час виконання.

## 📂 Структура файлів
*   **`HardwareProfile.h`**: Абстрактний інтерфейс для будь-якої архітектури.
*   **`X86HardwareProfile.cpp`**: Реалізація для x86 (Intel/AMD).
*   **`TenzoContext.cpp`**: Контейнер для MLIR контексту та HAL.

## 🛠 Ключові компоненти

### 1. `HardwareProfile::detect()`
**Принцип роботи:** Це статична фабрика, яка автоматично визначає платформу за допомогою `#ifdef` та викликає відповідний сканер.
*   **На x86**: Використовує асемблерну інструкцію `cpuid` для перевірки наявності AVX2, AVX-512 та VNNI.
*   **Топологія**: Аналізує `/sys/devices/system/cpu/` для визначення кількості фізичних ядер та розрізнення P-cores (продуктивних) та E-cores (енергоефективних).
*   **Кеші**: Зчитує розміри L1, L2 та L3 кешів, що критично важливо для коректного Tiling-у.

### 2. `TenzoContext`
**Принцип роботи:** Це центральний об'єкт, який утримує `MLIRContext` та активний `HardwareProfile`.
*   **Функція**: Під час компіляції він передає інформацію про розміри кешу в `MacroKernelPass`.
*   **Метод**: `context.registerDialect<tenzo::TenzoDialect>()` реєструє наші операції в MLIR.

### 3. `AutoTuner`
**Принцип роботи:** Якщо теоретичного профілю обладнання недостатньо, `AutoTuner` запускає швидкі мікро-бенчмарки для пошуку кращих параметрів (наприклад, розмір блоку матриці).

## 💡 Використання
Користувач може вручну вказати параметри обладнання, якщо він розробляє код для іншої системи:
```cpp
auto myHw = std::make_unique<X86HardwareProfile>();
myHw->setCacheSize(L2, 1024 * 1024);
TenzoContext tenzoCtx(mlirCtx, std::move(myHw));
```
Або покластися на автоматику:
```cpp
auto tenzoCtx = TenzoContext::detect(mlirCtx);
```
