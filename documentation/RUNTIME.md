# 🚀 Модуль: Runtime & Execution

Цей модуль відповідає за фізичне виконання скомпільованого коду на ядрах процесора або графічному прискорювачі.

## 📂 Структура файлів
*   **`TenzoEngine.cpp/h`**: Головний нативний C++ рушій виконання LLM (нуль динамічних виділень пам'яті).
*   **`ExecutionContext.cpp/h`**: Керування статичними scratchpad-буферами для всіх шарів трансформера.
*   **`KVCacheManager.cpp/h`**: Квантований KV-кеш (`int8_fused`, `tl1_fused`, PagedAttention).
*   **`MicroarchProfiler.cpp/h`**: Профілювання CPU та автоналаштування тайлінгу GEMV.
*   **`ThreadPool.cpp/h`**: Керування паралелізмом на CPU та прив'язка потоків до ядер (Thread Affinity).
*   **`VulkanRuntime.cpp/h`**: Керування обчисленнями на GPU через Vulkan 1.3 SPIR-V шейдери.
*   **`CUDARuntime.cpp/h` / `ROCmRuntime.cpp/h`**: Шари трансляції для апаратного прискорення.
*   **`HeteroPipeline.cpp/h`**: Гетерогенний конвеєр CPU-GPU та розподілені обчислення.
*   **`Sampler.cpp/h`**: Високопродуктивне Top-K / Top-P семплування на C++ min-heap.
*   **`Tokenizer.cpp/h`**: Байт-рівневий BPE токенізатор.
*   **`net/TenzoComm.cpp/h`**: Мережева взаємодія для розподіленого кластера.

## 🛠 Ключові компоненти

### 1. ThreadPool (Паралельне виконання)
**Принцип роботи:** Tenzo використовує власну реалізацію пулу потоків, адаптовану для MLIR.
*   **Thread Affinity (Прив'язка до ядер)**: Кожен потік пулу жорстко прив'язується до конкретного фізичного ядра процесора. Це критично для P/E-core архітектур, щоб уникнути перекидання важких обчислень на повільні ядра.
*   **ParallelFor**: Реалізує розподіл ітерацій (наприклад, рядків матриці) між потоками.
*   **Метод**: `pool.parallelFor(start, end, lambda)` розділяє діапазон за принципом статичного або динамічного планування.

### 2. Vulkan Runtime (GPU)
**Принцип роботи:** Дозволяє виконувати SPIR-V код (генерований MLIR GPU діалектом) на будь-якій відеокарті з підтримкою Vulkan.
*   **Device Discovery**: Шукає доступні фізичні GPU (інтегровані Intel iGPU або дискретні).
*   **Command Buffer**: Створює чергу команд для GPU, завантажує дані в GPU-пам'ять (VRAM) та ініціює обчислення.
*   **Метод**: `vulkan.execute(spirv_blob, bindings)` — низькорівнева функція для запуску ядра.

### 3. Execution Engine (JIT)
**Принцип роботи:** Використовує `mlir::ExecutionEngine` для перетворення MLIR модуля безпосередньо в двійковий код у пам'яті під час виконання програми.
*   **Оптимізація**: На цьому етапі LLVM застосовує фінальні низькорівневі оптимізації (LTO, Instruction scheduling).

## 🔄 Життєвий цикл виконання
1.  **Allocation**: Виділення вирівняної пам'яті (aligned memory) для тензорів.
2.  **Scheduling**: `ThreadPool` розподіляє роботу.
3.  **Kernel Execution**: Виклик JIT-функції або GPU-ядра.
4.  **Verification**: Порівняння результату з еталоном (якщо запущено в режимі тестування).

## 💡 Використання
Приклад запуску через ThreadPool:
```cpp
ThreadPool pool(hwInfo->getTopology());
pool.parallelFor(0, N, [&](int i) {
    // Обчислення i-го рядка
});
```
Запуск GPU тесту:
```bash
make gpu
```
